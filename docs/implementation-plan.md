# План реализации OctaReader

План основан на [спецификации MVP](./pwa-reader-project.md). Каждый пронумерованный шаг должен быть выполнен отдельным коммитом. Коммит не должен одновременно начинать следующий шаг.

## Статусы

- ⬜ **Не начат** — изменений для шага ещё нет.
- 🟨 **В работе** — изменения находятся в рабочем дереве, но коммит ещё не готов.
- ✅ **Выполнен** — существует завершённый коммит, прошедший предусмотренные проверки.
- ⛔ **Заблокирован** — продолжение требует решения или внешнего условия; причина указывается возле шага.

Статус шага обновляется в этом документе в том же коммите, который завершает шаг. Статус нельзя менять на «Выполнен», пока проверки не прошли и соответствующий коммит не подготовлен.

## Общие требования к каждому коммиту

- Коммит решает одну законченную задачу и не содержит несвязанных изменений.
- Проект собирается после каждого коммита.
- Начиная с добавления инструментов качества, перед коммитом выполняется `npm run validate`.
- Тесты функции добавляются вместе с функцией, а не откладываются до последнего этапа.
- Изменение схемы IndexedDB сопровождается версией Dexie, миграцией и тестом миграции.
- Обнаруженное ограничение Safari/iOS или `epub.js` нельзя молча обходить изменением требований — оно выносится на обсуждение.

## Этап 1. Основа проекта

### 1. Зафиксировать документацию проекта

**Статус:** ✅ Выполнен

**Коммит:** `chore: add project documentation and review instructions`

Добавить спецификацию, настоящий план и корневой `AGENTS.md` с правилами ревью в историю Git. Перед коммитом проверить ссылки и убедиться, что рабочее дерево содержит только документацию и инструкции проекта.

### 2. Создать Vue-приложение

**Статус:** ✅ Выполнен

**Коммит:** `chore: scaffold Vue application`

Создать Vue 3 + TypeScript + Vite-приложение, подключить Vue Router, зафиксировать версию Node, добавить `package-lock.json` и команды `dev`, `build`, `typecheck`.

Сразу включить строгую конфигурацию TypeScript:

- `strict`;
- `noUncheckedIndexedAccess`;
- `exactOptionalPropertyTypes`;
- `useUnknownInCatchVariables`;
- `noImplicitReturns`;
- `noFallthroughCasesInSwitch`;
- `noImplicitOverride`.

Не ослаблять эти параметры для обхода ошибок сторонних библиотек: несовместимые типы изолировать в небольших типизированных адаптерах.

**Проверка:** приложение запускается локально, TypeScript и production build проходят.

### 3. Добавить инструменты качества и тестирования

**Статус:** ✅ Выполнен

**Коммит:** `chore: add code quality and test tooling`

Настроить ESLint с flat config, Prettier, Vitest, Vue Test Utils и Playwright. Добавить команды `lint`, `lint:fix` и `npm run validate`, которая запускает typecheck, lint, unit-тесты и production build.

#### Ограничения ESLint

Использовать рекомендуемые type-aware правила `typescript-eslint`, правила Vue 3 и `eslint-config-prettier`. Линтер должен завершаться с ошибкой при любом warning (`--max-warnings=0`).

Обязательные ограничения для production-кода:

- запрет явного `any` и небезопасных операций с неизвестными значениями: `no-explicit-any`, `no-unsafe-assignment`, `no-unsafe-argument`, `no-unsafe-call`, `no-unsafe-member-access`, `no-unsafe-return`;
- обязательная обработка Promise: `no-floating-promises`, `no-misused-promises`, `await-thenable`;
- запрет неиспользуемых переменных и импортов; намеренно неиспользуемые параметры допускаются только с понятным префиксом `_`;
- обязательные type-only импорты через `consistent-type-imports`;
- запрет `console.*` и `debugger` в `src`; диагностические сообщения должны проходить через отдельный санитизирующий адаптер и не содержать API key;
- запрет нестрогого сравнения и неявных веток: `eqeqeq`, `curly`;
- запрет мутации Vue props и небезопасного HTML: `vue/no-mutating-props`, `vue/no-v-html`;
- запрет прямого использования `localStorage` и `sessionStorage` в `src`, поскольку пользовательские данные должны храниться через репозитории IndexedDB;
- запрет импортов тестовых модулей и dev-only зависимостей из production-кода;
- неиспользуемые `eslint-disable` считаются ошибкой.

Для тестов и конфигурационных файлов разрешены только узкие overrides. Не использовать глобальное отключение правил, файловые `eslint-disable` или понижение `error` до `warn` ради прохождения проверки. Локальное исключение допустимо только с комментарием, объясняющим конкретное техническое ограничение.

Prettier отвечает только за форматирование; правила форматирования не должны дублироваться в ESLint. Каталоги сборки, coverage и отчёты Playwright исключаются из lint.

**Проверка:** все команды проходят на чистом checkout; отдельные lint-fixture или RuleTester-проверки подтверждают, что опасные примеры действительно отклоняются, а overrides не распространяются на `src` целиком.

## Этап 2. Локальные данные и библиотека

### 6. Создать схему IndexedDB

**Статус:** ✅ Выполнен

**Коммит:** `feat: add IndexedDB database schema`

Подключить Dexie и создать версионируемую схему для книг, EPUB-файлов, locations, прогресса, настроек, кеша переводов, словарных записей, контекстов и повторений. Добавить доменные типы и репозитории.

**Проверка:** integration-тесты подтверждают создание базы, CRUD и повторное открытие сохранённых данных.

### 7. Добавить настройки приложения и книг

**Статус:** ✅ Выполнен

**Коммит:** `feat: add application and reader settings`

Реализовать хранение глобальных настроек отображения и направления перевода отдельно для каждой книги. Добавить конфигурацию AI с `DEFAULT_AI_MODEL = 'gemini-2.5-flash'`.

**Проверка:** настройки сохраняются после перезагрузки, а идентификатор модели определён только в конфигурационном слое.

### 8. Реализовать атомарный импорт EPUB

**Статус:** ⬜ Не начат

**Коммит:** `feat: implement atomic EPUB import`

Реализовать проверку EPUB, извлечение метаданных, хэширование содержимого, обнаружение дубликата и атомарную запись файла с метаданными через Dexie. Обработать повреждённый файл и `QuotaExceededError`.

**Проверка:** тесты подтверждают, что дубликат не создаётся, а после ошибки записи в базе нет частичной книги.

### 9. Реализовать экран библиотеки

**Статус:** ⬜ Не начат

**Коммит:** `feat: implement local book library`

Добавить импорт, список книг, обложку и метаданные, пустое состояние, ошибки импорта, предложение открыть дубликат и подтверждённое удаление книги.

**Проверка:** компонентные тесты покрывают основные состояния, импортированная книга остаётся доступной после перезагрузки.

## Этап 3. Читалка

### 10. Отобразить EPUB в reader

**Статус:** ⬜ Не начат

**Коммит:** `feat: render EPUB books`

Интегрировать `epub.js`, открывать сохранённый Blob, реализовать перелистывание, переход между главами и контролируемую ошибку рендеринга.

**Проверка:** тестовая EPUB-книга открывается из IndexedDB и позволяет перейти вперёд и назад.

### 11. Добавить оглавление

**Статус:** ⬜ Не начат

**Коммит:** `feat: add EPUB table of contents`

Добавить адаптивную панель оглавления и переход по её пунктам. Отсутствующее или повреждённое оглавление не должно мешать чтению.

**Проверка:** переход меняет главу; книга без TOC продолжает открываться.

### 12. Сохранять позицию и рассчитывать прогресс

**Статус:** ⬜ Не начат

**Коммит:** `feat: persist reader position and progress`

Реализовать генерацию и хранение `epub.js locations`, процент из EPUB CFI, состояние расчёта, сохранение позиции с debounce и восстановление после повторного открытия.

**Проверка:** изменение визуального размера страницы не меняет логический процент; повторное открытие возвращает пользователя к сохранённому CFI.

### 13. Подключить настройки отображения

**Статус:** ⬜ Не начат

**Коммит:** `feat: apply reader appearance settings`

Применять к содержимому EPUB размер и семейство шрифта, межстрочный интервал, поля и светлую/тёмную тему.

**Проверка:** настройки применяются без сброса CFI и сохраняются после перезапуска.

### 14. Определять слово и предложение

**Статус:** ⬜ Не начат

**Коммит:** `feat: detect tapped word and sentence`

Реализовать определение слова под тапом внутри содержимого `epub.js` и автоматический поиск предложения через `Intl.Segmenter` с fallback. Ручное выделение фрагмента не добавлять.

**Проверка:** тесты покрывают пунктуацию, апострофы, дефисы, границы абзаца и отсутствие предложения. Дополнительно выполнить ранний smoke-тест на реальном iPhone/Safari; нестабильность вынести на обсуждение до следующего этапа.

## Этап 4. Gemini и перевод

### 15. Создать абстракцию AI-провайдера

**Статус:** ⬜ Не начат

**Коммит:** `feat: add AI provider abstraction`

Создать интерфейс провайдера, тип `TranslationResult`, runtime-валидацию JSON, доменные ошибки и mock-провайдер. Бизнес-логика не должна зависеть от Gemini или идентификатора модели.

**Проверка:** unit-тесты покрывают все статусы и невалидные ответы.

### 16. Реализовать Gemini-провайдер

**Статус:** ⬜ Не начат

**Коммит:** `feat: implement Gemini translation provider`

Реализовать структурированный запрос с моделью из `DEFAULT_AI_MODEL`, контекстный перевод, lemma, часть речи, имена собственные, преобразование ошибок и единственный retry временной сетевой ошибки.

**Проверка:** тесты с подменённым HTTP покрывают успех, невалидный JSON, ошибки ключа, квоты, rate limit, сети и retry.

### 17. Добавить настройку и проверку API key

**Статус:** ⬜ Не начат

**Коммит:** `feat: add API key settings and validation`

Создать экран ввода, проверки и удаления ключа, статусы проверки и автоматическую проверку при первом переводе. Добавить санитизацию ошибок.

**Проверка:** ключ не попадает в URL, логи, кеш, сообщения и диагностические данные; offline-проверка не помечает ключ недействительным.

### 18. Добавить popup и кеш переводов

**Статус:** ⬜ Не начат

**Коммит:** `feat: add translation popup and cache`

Связать читалку с AI: сначала искать перевод в IndexedDB, затем обращаться к провайдеру. Показать загрузку, результат, ошибки, ручной повтор, слово, перевод, lemma, часть речи и предложение.

**Проверка:** повторный тап с тем же ключом кеша не выполняет сетевой запрос; сохранённый перевод доступен offline.

## Этап 5. Словарь и повторение

### 19. Реализовать хранение словаря

**Статус:** ⬜ Не начат

**Коммит:** `feat: implement vocabulary storage`

**Проверка:** одинаковая lemma с разными частями речи создаёт разные записи; одинаковое сочетание не дублируется.

### 21. Реализовать алгоритм интервального повторения

**Статус:** ⬜ Не начат

### 22. Создать экран повторения

**Статус:** ⬜ Не начат

**Проверка:** оценка немедленно обновляет расписание и исключает карточку из текущей очереди, если её новый срок ещё не наступил.

## Работа между чатами

Рекомендуемый размер одной рабочей сессии — один этап или примерно 3–5 коммитов. Новый чат стоит начинать после завершения этапа, при переходе к существенно другой подсистеме либо если текущая беседа накопила много логов, неудачных попыток и устаревших решений.

Новый чат не нужен после каждого коммита. В начале нового чата следует попросить прочитать:

1. `docs/pwa-reader-project.md`;
2. `docs/implementation-plan.md`;
3. `git status` и последние коммиты;
4. затем продолжить с первого шага со статусом «Не начат» или «В работе».

Так Git и документы остаются источником истины, а продолжение работы не зависит от полного текста предыдущей беседы.
